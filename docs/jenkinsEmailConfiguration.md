# Jenkins Email Notification Configuration

This document explains how each C14 Ticket System developer can configure email notifications for their **local Jenkins container**. Notifications are sent by `scripts/notify.py` after the pipeline finishes, whether the build succeeds or fails. **Email delivery is best-effort**: missing SMTP configuration, missing credentials, an unavailable SMTP server, or a Python error will produce a warning in the Jenkins console **without changing the build result**.

## 1. Prerequisites

- Docker and Docker Compose installed.
- The project cloned locally, with the unified `compose.yaml`.
- Python 3 installed **inside the Jenkins container** (`docker compose exec jenkins python3 --version`).
- A personal email account that supports SMTP authentication. For Gmail, enable 2-Step Verification and create a [Google App Password](https://myaccount.google.com/apppasswords), if supported for your account.
- The `scripts/notify.py` file committed to the repository.

> An app password is generated by the email provider. Do not use your ordinary Google password or invent a password. Never commit SMTP passwords, Jenkins credentials, or `.env` files.

## 2. Create your local `.env`

Copy the tracked example in PowerShell:

```powershell
Copy-Item .env.example .env
```

If no example is available, create `.env` at the repository root (next to `compose.yaml`). Configure the following values:

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_FROM=your-address@gmail.com
EMAIL_RECIPIENT=your-address@gmail.com
```

- `SMTP_FROM`: sender address; for Gmail it should match the authenticated account.
- `EMAIL_RECIPIENT`: recipient address; it may be the same as the sender. Multiple recipients can be separated by commas.
- `SMTP_HOST` and `SMTP_PORT`: SMTP provider connection settings; Gmail uses port `587` for STARTTLS.

The `.env` file must be ignored by Git. Keep the following entries in `.gitignore`:

```gitignore
.env
.env.*
!.env.example
```

**Do not put `SMTP_PASSWORD` in `.env`.** The username and app password are injected temporarily by Jenkins Credentials Binding.

## 3. Forward SMTP settings to the Jenkins container

Make sure the existing `jenkins` service in `compose.yaml` includes these environment settings (keep its other settings unchanged):

```yaml
services:
  jenkins:
    environment:
      SMTP_HOST: ${SMTP_HOST:-}
      SMTP_PORT: ${SMTP_PORT:-587}
      SMTP_FROM: ${SMTP_FROM:-}
      EMAIL_RECIPIENT: ${EMAIL_RECIPIENT:-}
```

If your Compose configuration uses an external Jenkins home volume, first supply the existing `JENKINS_HOME_VOLUME` value. Otherwise, keep the project's managed volume. Do **not** run `docker compose down -v` when you need to preserve Jenkins jobs and credentials.

Apply new environment variables by recreating only Jenkins:

```powershell
docker compose config
docker compose up -d --no-deps --force-recreate jenkins
```

## 4. Create your SMTP credential in Jenkins

1. Open [http://localhost:8081](http://localhost:8081).
2. Navigate to **Manage Jenkins → Credentials → System → Global credentials → Add Credentials** (menu labels may vary).
3. Select **Username with password**, with scope **Global**.
4. Set **Username** to your SMTP account address (for example, `your-address@gmail.com`).
5. Set **Password** to the Google App Password (or an SMTP-specific password supplied by your provider).
6. Set the credential **ID** to **`smtp-credentials`**, and save.

The credential ID must match the `credentialsId: 'smtp-credentials'` reference in `Jenkinsfile`. The pipeline exposes its values only during the notification step as `SMTP_USERNAME` and `SMTP_PASSWORD`.

Each developer running their **own Jenkins instance** should use their own SMTP credential. Do not distribute Railway production tokens or GHCR publishing tokens to other developers just to test notifications. On a shared Jenkins, a single authorized sender can notify multiple recipients.

## 5. Verify the setup

Run these commands from the repository root:

```powershell
docker compose exec jenkins python3 --version
docker compose exec jenkins printenv SMTP_HOST
docker compose exec jenkins printenv SMTP_FROM
docker compose exec jenkins printenv EMAIL_RECIPIENT
```

**Never print `SMTP_PASSWORD` in logs.** It is not expected to be a permanent container environment variable.

Run a Jenkins job against a test branch or PR. Confirm that the **Console Output** displays `Pipeline notification sent to ...` and that the recipient receives the email. A correctly identified PR branch skips the `main`-only GHCR push and Railway deployment stages.

## 6. Troubleshooting and expected behavior

| Symptom | What to check |
| --- | --- |
| `python3: not found` | Add Python 3 in `jenkins/Dockerfile`, rebuild Jenkins. |
| `Missing required environment variable` | Check `.env`, Compose's `environment` mapping, then recreate Jenkins. |
| `Credentials ... not found` | Add a global `Username with password` credential with ID `smtp-credentials`. |
| SMTP authentication failure | Check the full email address and provider-issued app password. |
| SMTP connection or TLS failure | Check SMTP host, port 587, networking and provider restrictions. |
| Email missing | Check recipient address, spam folder, and Jenkins Console Output. |
| `WARNING: Email notification could not be sent...` | The failure was caught; **the build result is unchanged**. Check settings and rerun. |

## 7. Behavior in the Jenkinsfile

The root-level `post { always { ... } }` block calls `python3 scripts/notify.py` after the pipeline stages and obtains credentials through `withCredentials`. It wraps only the notification step in `try/catch`:

```groovy
post {
    always {
        script {
            try {
                withEnv(["BUILD_STATUS=${currentBuild.currentResult}"]) {
                    withCredentials([
                        usernamePassword(
                            credentialsId: 'smtp-credentials',
                            usernameVariable: 'SMTP_USERNAME',
                            passwordVariable: 'SMTP_PASSWORD'
                        )
                    ]) {
                        sh 'python3 scripts/notify.py'
                    }
                }
            } catch (Exception ignored) {
                echo 'WARNING: Email notification could not be sent. The pipeline result is unchanged.'
            }
        }
    }
}
```

This means:

- A successful build **stays successful** if SMTP fails.
- A failed build **stays failed** even if email delivery succeeds or fails.
- Notification problems are visible in the Jenkins console, but they do not block CI/CD.
